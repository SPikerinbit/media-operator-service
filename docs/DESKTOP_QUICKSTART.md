# Media Operator 桌面快速开始

当前版本是 0.5.0。界面是一个双信箱工作台：首页同时放着「投稿」和「笔记」两个信箱，侧栏在信箱、投稿、笔记和设置之间切换。安装包未签名。系统缺少 WebView2 时，安装程序会联网补齐。

## 安装

在 Windows 11 x64 上运行 `MediaOperatorSetup.exe`，在安装位置页面选择目录。有 D 盘时，新安装默认选中 `D:\Media Operator`，否则选当前用户的本地程序目录。然后从桌面打开 Media Operator。

## 第一次打开

1. 打开「设置 → 转录与本地资源」，点击「检测本地环境」，并下载计划使用的 Whisper 模型。下载完成后可以离线转录。缺少模型时，任务会在处理素材前提示。
2. 在「设置 → 常规与目录」选择资料目录。
3. 需要翻译、投稿文案或观点摘录时，到「设置 → DeepSeek」保存模型和 API Key。密钥由 Windows 凭据管理器保存，不写入设置文件。
4. 需要投稿时，到「设置 → B 站投稿」保存创作中心凭据。
5. 需要把摘录写进笔记库时，先在 Obsidian 打开或创建一个 Vault，再到「设置 → Obsidian」选择该 Vault 的根目录。
6. 抖音或小红书需要登录才能读取时，到「设置 → 站点登录」按提示完成。

FFmpeg、ffprobe、yt-dlp 或 Deno 检测失败时，可重新运行安装程序修复。

## 投递来信

首页是两只信箱。左边投稿，右边笔记。把本地音视频路径、一条或多条链接，或整段分享文案写在信纸上。支持 YouTube、Bilibili、抖音、小红书和小宇宙，也支持本机文件。按 Enter 换行，Ctrl+Enter 或点击火漆投递。

应用会逐条识别标题、站点和类型。无法解析的纸条会退回，可以改完再投。已经在队列里的来信会标成重复。

侧栏的「投稿」和「笔记」是对应的工作台。投稿工作台的说明是「备齐设置，再点火处理」。笔记工作台会把来信整理成可以阅读的摘录。

## 投稿

来信识别成功后状态是「待设置」。四块木片对应四类设置：

- 输出：画幅、清晰度、Whisper 模型和推理模式
- 字幕样式：字体、字号和位置。随包提供思源黑体和思源宋体，也可以填写系统里已安装的字体名
- 投稿信息：标题、简介、分区、封面
- 翻译上下文：背景和术语

可以改「本次投递」里的全部稿件，也可以只改「当前稿件」。改过单条之后，可以「恢复继承」。在「设置 → 输出与字幕默认值」里保存的默认值，下次投递会带上。

四类都备齐后，点击「开始处理」。确认窗口会说明将要生成字幕和成片，并提交 B 站。勾选素材使用权限后再「确认并点火」。

处理中的纸条会显示阶段：获取素材、Whisper 转录、生成中文译文、烧录字幕、提交 B 站。失败或受阻时可以重试，或打开相关设置。投稿上传失败前，请先到 B 站稿件管理确认没有成功，再勾选后重试。成功的稿件可以打开投稿链接，旁边的放映机可以回看成片。

「输出 → 推理模式」里的严格 GPU 只使用本地模型和 CUDA，CUDA 不可用时会停下来。「烧录编码」可选自动、NVIDIA NVENC 或 CPU。自动优先 NVIDIA，不可用时回退 CPU。NVENC 只加速视频编码，字幕文字仍由 libass 绘制。

在「设置 → 转录与本地资源」可以下载 `large-v3-turbo`（约 1.62 GB）。在「转录加速」里选择 NVIDIA 运行库的安装目录后，可以启用 GPU。首次安装大约 1.2 GB。GPU 运行失败时，自动模式会改用 CPU 再试。

在线素材的预览和下载会读取 Windows 系统代理。

## 笔记

笔记信箱收下链接、分享文案、音视频，以及已有的 SRT 或 VTT。处理完成后，工作台上是原文和观点卡片。点击时间戳回到原话。可以编辑译句、主题和说明，再发布到已选择的 Obsidian Vault。

每张卡生成一篇观点笔记，并链接到共享素材页。发布成功并核对写入之后，对应的本地草稿会清掉。重复发布会指回原来的笔记。另存新版本会写成独立文件。发布失败的草稿可以重试。

同一条素材如果已经在投稿流程里做过下载、转录或翻译，笔记侧会复用这些结果，只继续整理。

## 从源码构建

需要 Windows x64 的 Python 3.12、Node.js 24 和 Inno Setup 7。在仓库根目录安装 `requirements-desktop.txt`，然后运行 `scripts/build_desktop.ps1`，传入构建目录、输出目录、`ISCC.exe` 和 Python 解释器。脚本会安装锁定的前端依赖，把生成的静态资源打进安装包。版本号读仓库根目录的 `VERSION`。

路径用本机环境变量，不要把个人目录写进仓库。示例见 `AGENTS.md`。

## 无界面 API

可选的无界面服务见仓库根目录的 `Dockerfile`、`docker-compose.yml` 和 `scripts/serve_api.sh`。它和桌面程序共用处理流水线，但没有桌面这套本机会话。默认只监听 `127.0.0.1`。要绑到其他地址，必须先设置 `MEDIA_API_TOKEN`，请求里带上 `Authorization: Bearer <token>` 或 `X-Media-Token`。桌面程序不使用这个令牌。
