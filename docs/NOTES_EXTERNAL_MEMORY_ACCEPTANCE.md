# 0.5.0 笔记外存聚合验收记录

本轮保持版本 0.5.0。笔记生成由 `app/note_engine.py` 接管，数据库保存运行、原文范围、节点、观点、重复关系、译文和请求预算审计；接口、界面和 Markdown/SRT/Obsidian 导出使用有限页或流式写入。

## 已落地

- 完整消息发送前检查输入上限 6144、最大输出 4096、安全余量 1024，并按配置容量缩小。UTF-8 字节数作为保守 token 上界，真实消耗另用服务端 usage 登记。概述序列化后不超过 512 字节，因此也不超过 512 token；这一实现比计划的 token 限制更保守。
- 每块按句末和 Unicode 字符边界组织原文范围；最多 24 个局部片段。两路请求并发，待办和检查点保存在 SQLite。翻译扩张、截断和全面档 overflow 严格二分；单字符仍失败则停止并保留原因。
- 四叉概述归并，小容量改二叉；超长概述只紧缩重试一次。详细观点不会装入根概述或全篇筛选请求。
- 精华按主题轮选、评分及来源排序；最多八项进行重复确认；全面档保留详细候选和重复出现的来源关系。摘要通常生成 3–6 张卡。
- 成功前校验原文范围连续且全覆盖。成功后原子切换当前自动稿；手改和旧自动稿仍留库；回切成功档位复用结果与卡片 ID。
- 崩溃时正在运行的笔记任务在启动后续作；明确失败的模型任务保留检查点供重试。投稿仍保留原来的手动恢复策略。
- 原文与卡片每页最多 64 项，引用每页最多 32 项。超长原文继续分段阅读；译文从数据库分页加载，不再下载整份译文到 DOM。
- GPU 转录与 NVENC 烧录共享 FIFO；OOM 使用新的 GPU worker、batch 1 重试；严格 GPU 不转 CPU。
- 抖音 Aweme 时长按毫秒转换，播放器候选只取目标作品数据，逐候选记录实际时长与拒绝原因；信箱终态同步到持久化记录。

## 验收证据

生成的本机证据在仓库忽略的 `data/` 下，不将个人素材和凭据提交仓库。

- 后端：114 项通过，`data/notes-tests-install.log`；新增预算拒发、二叉归并、覆盖缺口、最小片段终止、恢复、切档稳定 ID、GPU FIFO 与 OOM 测试。
- 前端：TypeScript / Vite 构建通过；`data/notes-ui-final.log` 验证三档请求、键盘、手改、44 个布局及焦点；`data/notes-motion-final/results.json` 验证进纸、碎纸、撤销、分页定位和减少动态效果。
- 百万合成片段：`data/notes-scale-acceptance/results.json`。真实 SQLite 分页扫描 1 / 1000 / 1000000 个片段，页上限 64，Python tracemalloc 峰值分别 1281 / 26755 / 37955 字节。这是外存分页压力测试；百万叶子的完整模型调用没有执行，树高数据是调度规模推算，不冒充端到端实测。
- 中文小宇宙长稿：数据库副本 transcript 16，56/56 块完成，生成 3 张摘要卡；累计输入 45194、输出 13720 token，包含失败及恢复期间的实际消耗。
- 长英文字幕：副本 transcript 12，18/18 块完成，生成 3 条精华；累计输入 24977、输出 14965 token，翻译缓存可跨档位复用。
- 全面档人工构造样本：16 条带条件的独立规则，生成 17 条观点（密码规则拆成两项）。逐条阅读涵盖 16 条规则；简单关键词匹配为 13/16（81.25%，同义表述会漏计）。累计输入 2585、输出 2275 token。证据：`data/notes-real-acceptance/annotated-results.json`。这不是独立人工评测语料的统计召回率。
